# 3D 模型编辑器设计文档

## 目标

在现有项目中搭建一个轻量级 3D 微景观创作体验。编辑器以项目内置的默认 3D 素材为核心，用户可以把素材拖到舞台中进行创作；同时也允许用户上传自己喜欢的 GLB/GLTF 文件，用作个人创作素材。

整体体验应该像一个轻量 3D 编辑器，而不是完整建模软件。用户通过现成素材组合场景，调整位置、旋转、缩放等变换，然后把当前画布保存为图片。

## 已确认范围

V1 包含：

- 项目提供默认 3D 素材库。
- 用户可以上传 GLB/GLTF 素材。
- 用户可以从默认素材拖拽素材到 3D 舞台。
- 用户可以选中场景中的元素。
- 支持移动、旋转、缩放、复制、删除、重置选中元素。
- 支持常见编辑操作的撤销和重做。
- 支持把当前画布视角保存为 PNG 图片。
- 保留当前季节容器和微景观视觉方向。

## 当前项目背景

项目当前已经使用：

- Next.js 16.2.10。
- React 19.2.4。
- Three.js 0.180.0。
- @react-three/fiber。
- @react-three/drei。
- @react-three/postprocessing。
- Zustand 管理编辑器状态。

现有编辑器已经具备 3D 画布、季节容器、预设基础几何素材、拖拽放置、选中、基础移动按钮、PNG 导出和本地状态持久化能力。

本设计是在现有架构上扩展，而不是重写编辑器。

## 用户体验

工作台打开后展示默认素材。素材浏览器至少包含两个分组：

- 默认素材：项目内置的精选 3D 模型。
- 我的素材：用户上传的 GLB/GLTF 文件。

用户从任意分组拖拽素材到 3D 舞台。模型会出现在微景观容器中的投放位置，并且新添加的元素会自动变为选中状态。

当元素被选中后，编辑器展示变换控制器和属性面板。用户可以直接在画布中拖动、旋转、缩放元素，也可以在侧边栏中通过按钮或数值控件调整。

导出流程保持简单：一个按钮把当前画布视角保存为 PNG 图片。

## 素材数据模型

新增一种元素类型：

- model-3d

素材记录应支持：

- id
- name
- category
- kind
- previewUrl
- modelUrl
- sourceType: preset | upload | remote
- color 和 accent：仅在基础几何或生成类素材需要时使用
- scale 或 defaultScale

项目场景元素应支持：

- id
- assetId
- name
- kind
- category
- position
- rotation
- scale
- modelUrl
- sourceType
- previewUrl

V1 中，`scale` 可以继续保持单个数字，以减少对现有数据结构的改动。如果后续 TransformControls 需要非等比缩放，可以新增 `scale3: [x, y, z]`，同时保留现有 `scale` 字段以兼容旧数据。

## 默认素材库

默认素材应使用项目本地文件，建议路径：

- `public/assets/models/`
- `public/assets/previews/`

建议素材分类：

- 植物
- 石头
- 建筑
- 装饰物
- 角色
- 地形

每个默认素材应包含预览图；如果暂时没有预览图，可以使用备用预览卡片。默认素材库应在没有网络的情况下也能使用。

## 用户上传

上传控件接受：

- `.glb`
- `.gltf`

上传后的文件加入“我的素材”。V1 中，上传素材只服务本地创作和图片导出。因为分享不在范围内，系统不需要让上传文件在其他用户或其他设备上可用。

持久化选项：

- V1 推荐：把上传的 GLB 文件转成 data URL，存入 Zustand 持久化状态。你提供的测试 GLB 约 254 KB，适合这种方案。
- 保护措施：对过大的文件进行拒绝或警告，避免撑爆 localStorage。
- 未来选项：如果用户经常上传较大的资产，可以改用 IndexedDB。

## 场景渲染

`SceneItems` 应根据元素类型分发渲染逻辑：

- 现有基础几何元素继续使用当前 mesh 组件。
- `model-3d` 使用基于 drei `useGLTF` 或 `GLTFLoader` 封装的 GLTF 模型组件。

模型组件应做到：

- 加载 `modelUrl`。
- 将过大或过小的导入模型归一化到合理默认尺寸。
- 尽量根据模型视觉包围盒居中。
- 和基础元素保持一致的选中提示。
- 如果模型加载失败，显示一个可见的占位元素。

## 画布编辑

为选中元素添加 `TransformControls`。

编辑模式包括：

- 移动
- 旋转
- 缩放

当 `TransformControls` 正在操作时，应临时停止 `OrbitControls` 响应拖拽，避免用户编辑模型时视角也跟着旋转。

侧边栏属性面板应提供：

- 选中元素名称。
- 模式切换：移动、旋转、缩放。
- 复制。
- 删除。
- 重置变换。
- 如果和现有 UI 合适，可以加入位置、旋转、缩放的数值控件。

现有移动按钮可以保留，也可以替换为更清晰的属性面板。

## 撤销与重做

围绕项目编辑操作增加历史记录。历史记录应覆盖：

- 添加元素。
- 删除元素。
- 复制元素。
- 移动元素。
- 旋转元素。
- 缩放元素。
- 重置变换。
- 修改季节。
- 修改容器。

历史记录只需要作用于当前项目编辑会话。V1 不要求刷新浏览器后仍保留撤销栈。

实现时应避免在连续拖动过程中记录过多快照。一次变换拖拽可以在拖拽开始时记录旧状态，在拖拽结束时提交新状态。

## 保存图片

保留单一导出动作：

- 保存 PNG。

导出的图片应和当前可见画布视角一致。不需要导出倍率选择器。

如果当前导出依赖 `preserveDrawingBuffer`，可以继续保留该设置。

## 错误处理

上传错误：

- 文件类型不支持：显示简短 toast。
- 文件过大：显示简短 toast，不导入。
- 模型解析失败：不添加素材，并显示简短 toast。

渲染错误：

- 如果模型添加后加载失败，场景中显示一个简单占位元素，并保持该元素可选中，方便用户删除。

编辑限制：

- 保留当前容器边界规则，避免元素漂移到微景观外部。
- 对缩放值设置合理上下限，避免模型变得不可见或过大。

## 测试与验收

验收应覆盖：

- 你提供的 GLB 文件可以上传，并出现在“我的素材”中。
- 默认模型可以拖到舞台。
- 上传模型可以拖到舞台。
- 选中元素后可以移动、旋转、缩放。
- 复制和删除可用。
- 撤销和重做可以恢复场景变化。
- 保存 PNG 可以下载当前可见画布。
- 在支持的文件大小范围内，浏览器刷新后本地上传素材仍能恢复。
- TypeScript 和 lint 检查通过。
- 生产构建通过。

## 实现注意事项

在修改 Next.js 代码前，必须按 `AGENTS.md` 要求，先阅读 `node_modules/next/dist/docs/` 中相关的本地 Next.js 16 指南。

实现应尽量贴合当前项目模式：

- 继续使用 Zustand 作为编辑器状态源。
- 扩展现有 `LibraryAsset` 和 `ProjectItem` 类型。
- 扩展 `SceneItems`，不要替换整个场景渲染器。
- 保留当前季节视觉风格和容器系统。
- V1 避免引入云端或后端存储。

## 未决问题

V1 没有阻塞性的产品决策。

合理的实现默认值：

- 默认上传大小限制：5 MB，除非测试显示 localStorage 需要更小限制。
- 初始变换模式：移动。
- 新拖入元素：立即选中。
- 上传素材分类：uploaded。
- 上传素材来源类型：upload。
